# 키보드 성벽 도트 시안 3종

2026-10-20. 첨부된 팀원 시안의 아이보리 키캡·검은 프레임·주황 배선을 참고하여 내장 imagegen으로 생성했다. 기존 사람 캐릭터 이미지는 크기와 도트 표현 참고용으로 사용했다. 흙과 잔디 장식은 성벽 PNG에 포함하지 않았다.

## 파일

원본 위치: `Assets/Art/KeyboardCastleConcepts/20261020/`

| 시안 | 투명 PNG | 특징 | Unity 조립 미리보기 |
|---|---|---|---|
| A | a-keycap-block.png | 큰 키캡, 기본형 실루엣 | preview-a.png |

각 PNG는 1254×1254 RGBA이며 실제 투명 알파를 포함한다. 이미지 픽셀을 사후 수정하지 않고 원본을 보존했다. `prompts.json`에 세 시안의 전체 생성 프롬프트를 저장했다.

## Unity에서 사용

Project 창에서 `Assets/Art/KeyboardCastleConcepts/20261020`을 열고 PNG의 펼침 화살표를 누르면, 시안별 8개 스프라이트를 선택할 수 있다. 총 24개다.

| 이름 | 용도 |
|---|---|
| A/B/C_L_Top | 왼쪽 성벽 상단 |
| A/B/C_L_Middle | 왼쪽 성벽 반복 중간 |
| A/B/C_L_Bottom | 왼쪽 성벽 하단 |
| A/B/C_L_Opening | 왼쪽 성벽 파손·뚫린 구간 |
| A/B/C_R_Top | 오른쪽 성벽 상단 |
| A/B/C_R_Middle | 오른쪽 성벽 반복 중간 |
| A/B/C_R_Bottom | 오른쪽 성벽 하단 |
| A/B/C_R_Opening | 오른쪽 성벽 파손·뚫린 구간 |

원본 시트는 윗줄이 왼쪽, 아랫줄이 오른쪽이며 각 줄의 순서는 상단 / 중간 / 하단 / 파손이다. 스프라이트는 동일 크기 격자 대신 실제 그림의 범위와 연결부를 기준으로 잘랐다. 좌표는 `sprite-layout.json`에 기록했다.

- Sprite Mode: Multiple, Filter Mode: Point, 압축 없음, 밉맵 없음.
- Pixels Per Unit: 156.75. 현재 사람 캐릭터의 PPU 32와 함께 배치했을 때 키캡이 대략 캐릭터 몸통 정도가 되는 비교용 크기다.
- 피벗은 아래쪽 및 바깥 프레임 축을 기준으로 맞췄다. 왼쪽끼리 또는 오른쪽끼리 같은 X에 배치하고, 다음 부품의 Y를 현재 Y + `sprite.bounds.size.y × scale.y`로 잡아 쌓는다.
- 조립 순서는 하단 → 중간 반복 → 필요 시 파손 구간 → 중간 반복 → 상단이다. 모듈별 높이가 달라 좌우를 같은 개수로 쌓아도 꼭대기 높이는 다를 수 있다.
- 최종 맵에서는 그림과 별도로 실제 발판·벽 충돌체를 설정한다. 파손 구간의 배선이나 장식 조각이 자동으로 통행 가능한 충돌 구멍을 만드는 것은 아니다.

## 확인 범위와 남은 조정

Unity에서 3종 모두 8개 스프라이트로 가져오고 실제 캐릭터와 기존 XP풍 배경을 넣은 임시 조립 렌더로 크기를 확인했다. 미리보기는 정지 이미지이며 실제 플레이 화면을 녹화한 것은 아니다.

중간 부품은 위아래 연결부를 골라 반복할 수 있게 잘랐으나, AI 생성 특성상 서로 다른 모듈의 배선·키캡·외곽선이 모든 경계에서 픽셀 단위로 완전히 일치하지는 않는다. 최종 채택 후 경계 일부를 다듬을 수 있는 디자인 시안이다. 시안끼리 섞어 쓰는 연결성은 보장하지 않는다.

기존 MainScene의 성벽·배경·충돌체는 이번 시안 생성으로 교체하지 않았다. 임시 렌더 오브젝트는 저장하지 않고 제거했다.
