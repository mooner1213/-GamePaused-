# 팀원 옥상 원화 · 15테마

> 이 문서는 최초 SpriteRenderer 배치 버전의 기록이다. 현재 편집용 자산과 씬은 [실제 Tilemap · 가로 연결 개정](../RooftopGrid20261028/README.md)을 따른다. 사용자가 허용한 가로 너비 수정과 여백 제거를 적용했으므로 현재 타일은 아래의 최초 원본 윤곽 유지 조건과 구별한다.

원본: `Source.png` — 사용자가 전달한 KakaoTalk_20261028_164614790.png 사본.

1·3·5번째 줄을 사용하고 2·4번째 줄은 전부 제외했다. 원본 PNG는 수정하지 않는다. 검은 바탕만 투명하게 만들고, 남긴 픽셀은 같은 좌표에서 색상표만 바꾼다. 균열·문양·기둥·깃발·잔해의 형상은 재생성하지 않는다.

- 첫 줄 5개: 캐릭터 뒤의 옥상 성벽.
- 셋째 줄 5개: 캐릭터 앞의 옥상 난간.
- 다섯째 줄 9개: 깃발 2종, 잔해 7종.
- 전체 19개 부품 × 15테마. 원화의 빈 줄을 투명하게 남겨 원본 좌표 비교가 가능하다.

내장 image_gen 도구로 만든 `RGB색상시안.png`는 색상 참고용이다. 생성 시안에 있었던 미세한 위치 변화는 게임용 자산에 사용하지 않았다. 최종 PNG는 원본에 같은 색상표를 좌표별 적용한 결과다. Python 또는 외부 이미지 API는 사용하지 않았다.

image_gen에 전달한 편집 조건: 원본의 2·4줄 전체 제거, 1·3·5줄의 개별 부품 위치·형상·크기·비율·균열·외곽선 유지, 09 RGB 키보드에 맞는 짙은 회청색 재질과 청록/분홍 발광색, 투명 배경, 글자·새 장식·추가 형태 금지. 나머지 14테마는 기존 `Themes.json`의 테마색과 재질 명암표를 사용한다.

최종 그림: `Assets/Art/RooftopThemes20261028/<테마>/옥상_1·3·5줄.png`.

팔레트: 기존 15개 테마 팔레트와 `00 전체 벽 디자인 · 15종` 아래쪽에 추가했다. 옥상만 모은 `16 옥상 성벽 · 15테마` 팔레트도 제공한다. 원화 128픽셀이 월드 1칸이며 조각이 칸을 채우려고 늘어나지 않는다. 부분 칸의 남는 영역은 투명하다.

씬 계층: `08 테마 옥상 · 원화 1·3·5줄` 안의 `01 옥상 뒤 성벽`, `03 옥상 앞 난간`, `05 깃발과 잔해`. 각 계층에는 편집용 Tilemap이 있다. 연결된 원화 부품은 균등 배율의 SpriteRenderer이며 개별 이동/비활성화가 가능하다. 기존 옥상 뒤 난간의 Tilemap 데이터는 보존하고 렌더러만 끈다.

## 2026-10-28 검증 결과

- 15개 최종 PNG의 윤곽 차이 0. 각 시트의 불투명 픽셀 287,397개, 삭제한 2·4줄의 잔존 픽셀 0. 모두 1448×1086 원본 해상도와 Point 필터로 가져왔다. 테마별 파일 해시는 15개 모두 다르다.
- 19부품 × 15테마의 전체 타일 285개, 분할 타일 1,230개. 기존 개별 테마·전체 모음·옥상 전용 모음에 연결된 3,690개 분할 타일에서 Sprite 누락 0.
- 15개 테마 씬과 MainScene 저장 완료. 각 씬에는 새 장식 SpriteRenderer 35개와 편집용 Tilemap 3개가 있다. 작은 정상 발판이 있는 씬에서도 성 양쪽 외벽 안쪽의 전체 폭으로 장식을 배치한다.
- 저장 전후 기존 Transform·Tilemap·Collider 블록 비교에서 부모의 새 자식 참조 외 변경 0. 기존 뒤 난간의 Tilemap 데이터도 보존했다.
- 15개 테마의 실제 Unity 월드 렌더링을 캡처했다. 기존 하층 배경·발판·출구는 유지했다.
- 09번 Editor Play에서 앞 난간 ON/OFF와 캐릭터 ON/OFF를 조합한 4장 렌더 비교: 캐릭터 픽셀 784개가 앞 난간으로 가려지고 2,387개가 계속 보였다. 뒤 성벽 순서 -15, 플레이어 20, 앞 난간 30.
- 같은 실행에서 ESC → 점프 → 문구 파괴 → 어퍼컷 03번 자세 → 크레딧과 Y 443까지 계속 상승 확인. 새 배치 이후 재시작도 실행했다.
- 최종 Console 오류·경고 조회 0건. Play 종료 후 09번 씬이 저장된 상태로 열려 있다.

이 검증은 Editor의 자동 입력과 카메라 렌더링 결과다. 새 Windows/APK 빌드나 기기 실행 검증은 하지 않았다.
