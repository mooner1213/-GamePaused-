# 2026-10-21 · 09 RGB 메인과 팔레트 편집

이 문서는 최초 RGB 수정 당시의 기록입니다. 이후 팔레트를 한 칸씩 분할하고 카메라·잔상·입체 발판을 수정했습니다. **현재 편집 방법과 검증은 [칸별 편집 안내](../GridRevision20261021/README.md)를 확인하세요.** 아래 331개 전체 그림 타일은 연결 호환용으로 보존하며 기본 팔레트는 분할 조각 1,579개를 사용합니다.

메인 씬은 `Assets/Scenes/MainScene.unity`입니다. **09 RGB 키보드**를 적용했고, 같은 발판·장치 배치를 가진 비교 씬 15개는 `Assets/Scenes/DesignStages`에 보관합니다. 기존 106개 발판의 ID·재질·좌표·너비·경사·이동 설정은 변경 전 기록과 일치합니다.

## 바로 편집하기

Unity 상단 메뉴 **일시정지 게임 → 팔레트 → 09 RGB 메인 편집 열기**를 누르면 메인 씬, Tile Palette, 성벽 채우기 대상을 함께 엽니다. 재생하지 않은 상태에서 칠하고 씬을 저장하세요.

`06 팔레트 편집 Grid · 빈칸을 직접 칠하기` 아래에 세 편집 대상이 있습니다. Tile Palette의 **Active Tilemap**을 골라 사용합니다.

| 대상 | 용도 |
|---|---|
| `01 성 내부 벽 · 장식만 · 빈칸 채우기` | 캐릭터와 발판 뒤의 성벽 배경. 벽·정사각 채우기·장식 타일을 칠합니다. 이 레이어는 착지 판정을 만들지 않습니다. |
| `02 창문 레이어 · 창틀과 안쪽 구멍` | 창문 타일을 칠합니다. 창틀 주변의 성벽은 유지되고 창문 안쪽만 뚫립니다. 창문을 지우면 구멍도 함께 없어집니다. |
| `03 발판 추가 · 실제 착지 판정` | 일반·기름·금간·타이머 발판 타일을 칠합니다. 다음 Play에서 실제 물리와 예상 궤도에 같은 착지 표면이 추가됩니다. |

창문은 **09 팔레트의 `창틀_투명한 창문`**, 다른 테마는 **`연결벽_Window`**를 창문 레이어에 칠하세요. 창문 주변을 지우거나 별도 직사각형 구멍을 만들 필요가 없습니다. 창문 오브젝트 또는 Tilemap 자체를 이동하면 안쪽 마스크도 함께 이동합니다.

발판 타일은 원래 한 셀보다 넓습니다. 넓은 발판을 연속해서 놓을 때는 그림과 실제 상단을 보고 셀 간격을 두세요. 타일을 수직으로 돌리면 착지 표면으로 사용할 수 없어 Console 오류로 알려줍니다.

기존 106개 발판은 원래의 개별 오브젝트로 남아 있습니다. 위치·너비·경사는 해당 오브젝트 Inspector에서 수정합니다. 외형 교체는 `팔레트 디자인 교체`에 발판 타일을 넣거나, 팔레트에서 발판 하나를 고른 뒤 **팔레트에서 고른 발판 디자인 적용**을 누릅니다. 일반 발판은 선택한 재질로 변경되고, 최종 네 발판과 정상 발판은 엔딩용 역할을 유지합니다.

## 벽과 발판 자산

- `Assets/Palettes/StageDesigns`: 테마별 15개 + 전체 모음 1개, 실제 Unity Tile Palette.
- `Assets/Tiles/StageDesigns`: 타일 331개. 팀원·기존 생성 이미지의 좌우 시작·몸통·끝·파손 등 원본 모듈 144개도 포함합니다.
- `Assets/Art/RGBMain20261021`: 새 RGB 발판·창틀·성벽·독립 배경 도트. 필터는 Point, X/Y 균등 배율로 원본 비율을 유지합니다.
- 원본 이미지 파일은 보존했습니다. 검정 배경이 있던 최초 팀원 이미지는 투명 파생본을 별도 생성했습니다. 생성 프롬프트와 원본 경로는 `Prompts.json`에 있습니다.
- `Sprites/WindowMasks`의 흰색·투명 Texture2D는 창문 안쪽만 가리는 기술 데이터입니다. 화면에 그림으로 표시되는 자산은 아닙니다.

| 발판 | 표시와 동작 |
|---|---|
| 일반 | 테마에 맞는 단단한 발판 |
| 기름 | RGB 메인은 검은 유막·광택·흘러내림. 기존 미끄러짐 물리와 바람의 추가 밀침을 유지합니다. |
| 금간 | 금이 간 그림. 정지 시작 때 무너지는 기존 일회성 발판 규칙을 유지합니다. |
| 타이머 | 중앙 아래에 도트 **3 → 2 → 1** 표시 후 소멸. 카운트는 기존 기획대로 ESC 정지 중에도 흐릅니다. |

내부 방향 전환 벽과 **중간 스킵 포탈 4개**는 제거했습니다. 외곽 두 벽은 유지합니다. **정상 101번 발판의 마지막 출구**는 16개 씬 모두에 한 개씩 복원했습니다. 최종 네 도약과 정상 도착 후 ESC·점프 키로 실행하는 어퍼컷 엔딩은 기존 판정을 사용합니다.

## 독립된 배경 레이어

`05 입체 배경 · 거리별 네 겹` 아래에 실제 깊이가 다른 부모 오브젝트로 나눴습니다. 각각의 그림을 편집 화면에서 따로 선택·이동할 수 있습니다. 성벽 배경과 창문은 월드에 고정되며, 창문 안쪽과 성 외부로 원경을 볼 수 있습니다.

| 레이어 | 깊이 Z | 카메라 추종 X / Y |
|---|---:|---:|
| 하늘 | 40 | 0.96 / 0.96 |
| 구름 | 32 | 0.84 / 0.86 |
| 먼 성곽 | 24 | 0.68 / 0.78 |
| 가까운 건축물 | 16 | 0.32 / 0.46 |

추종 값이 1에 가까울수록 화면에서 천천히 스쳐 가므로 멀리 보입니다. `Pause Design World View`의 거리별 배경 움직임에서 조절할 수 있습니다. 배경 그림은 카메라마다 새로 생성하지 않으며, 하늘은 45~175m에서 기존 높이 그라데이션으로 색이 변합니다. ESC 정지 중에는 시차 이동도 정지합니다.

## 이번 작업의 검증 범위

- `Docs/Validation/RGBMain20261021/DesignValidation.json`: **565개 조건 통과**. 16씬의 배치 보존·균등 벽 배율·팔레트·별도 창문·최종 출구 연결, 타일을 칠한 뒤 저장·다시 열기와 실제/예측 표면 일치.
- `Runtime/RuntimeValidation.json`: **실제 Unity Editor 재생 16/16 통과**. 카메라 이동에 따른 네 배경의 이동량, 정지와 원색 복구, 시작점 두 도약. 메인은 실제 게임 Tick의 도트 3/2/1 카운트도 확인했습니다. 이 폴더의 PNG는 해당 재생 화면입니다.
- `ExpansionValidation.json`, `FeedbackValidation.json`: 현 버전의 기존 물리·회복·트램펄린·낙하 카메라 회귀 검사입니다. 고립 물리 실험의 포탈 사례는 코드 회귀 검사이며 씬에 스킵 포탈이 있다는 뜻이 아닙니다.
- `Docs/Art/StageThemes20261020/Previews`: 하층·중층·상층의 **Editor 정적 렌더**입니다. Play 녹화와 구분합니다.

Android 실기기, 175m 전체 완주, 성능 측정은 이번 범위에 포함하지 않았습니다. 이전 Windows/APK 실행 파일에는 이번 수정이 포함되지 않습니다.

팔레트 준비 메뉴는 자산을 생성하는 제작 도구입니다. 맵을 수동 편집한 뒤에는 씬 전체 디자인 재적용을 사용하지 마세요. 기본 재적용은 기존 편집 Tilemap을 발견하면 덮어쓰기를 거부하도록 되어 있습니다.
