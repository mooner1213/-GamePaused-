# [일시정지!(가제)] Unity C# 코딩 기본 규칙 (Codex / AI 지침서)

본 문서는 2D 타임스톱 등반 플랫포머 **《일시정지!(가제)》**를 유니티(Unity)에서 제작할 때, AI 코딩 도구(Codex, Cursor 등)와 작업자가 일관되고 체계적인 코드를 작성하도록 강제하는 **[기본 규칙]**입니다. AI에게 코드 생성을 요청할 때 이 문서를 시스템 프롬프트나 프로젝트 루트 규칙(`AGENTS.md`, `.cursorrules` 등)으로 등록하여 사용하세요.

---

## 1. 프로젝트 개요 및 핵심 기믹 (AI 컨텍스트 인지용)

코드를 작성할 때 반드시 아래 게임의 핵심 규칙을 전제로 설계해야 합니다.

* **장르 및 그래픽**: 2D 도트 그래픽 횡스크롤/수직 등반 플랫포머
* **조작 체계 (방향키 없음)**: 좌/우 이동키 없이 오직 **`Space`(점프 세기 충전 및 연속 도약 입력)**와 **`ESC`(일시정지 토글 및 예약 실행)**, **`마우스`(우측 상단 설정 UI 및 엔딩 상호작용)**만 사용합니다.
* **일시정지 사전 입력 (Recording) & 재생 (Playback)**:
  * `ESC`를 누르면 시간이 멈추고(흑백/불투명 연출, 사운드 정지) 사전 입력 상태가 됩니다.
  * 일시정지 상태에서 `Space`를 누른 시간(Hold Duration)에 비례해 점프 강도가 결정되며, 여러 번 누르면 **연속 점프가 큐(Queue/List)에 순서대로 예약**됩니다.
  * 다시 `ESC`를 누르면 일시정지가 해제되며 예약된 점프들이 순서대로 자동 실행됩니다.
  * **재입력 잠금 규칙**: 예약된 연속 점프가 모두 소모되기 전까지는 중간에 `ESC`로 화면을 멈추더라도 **추가 점프 입력을 받을 수 없습니다.**
* **벽 박치기 방향 전환**: 캐릭터는 걸을 수 없으며 현재 바라보는 방향으로만 포물선 도약을 합니다. **반대 방향으로 전환하려면 반드시 벽이나 구조물에 박치기(충돌)해야만** 반사되며 시선이 반대로 바뀝니다.
* **보조 궤도 가이드 (Trajectory Guide)**: 초반 구간에서는 사전 입력 중인 연속 점프와 벽 반사 예상 궤도가 선명하게 표시되지만, 등반 높이에 따라 단계적으로 축소·비노출됩니다. (단, 궤도 계산과 실제 이동 물리는 100% 동일한 수식을 공유해야 오차가 발생하지 않습니다.)
* **특수 발판 및 기믹**:
  * **얼음 발판**: 착지 시 미끄러지며 벽 박치기 반사 유발 (평지 및 오르막/내리막 경사 포함).
  * **3초 파괴 발판**: 밟는 순간 3초 타이머 게이지 UI가 작동하며(`ESC` 일시정지 상태에서도 게이지 UI가 보임), 3초 후 파괴됩니다.
  * **구름 발판**: `ESC` 일시정지 상태에서 연속 점프 설계를 통해 통과해야 하는 발판.
  * **정상 및 후반부 반전 연출**: 탑 정상 도달 시 화면 상단의 `'일시정지'` UI 텍스트가 플레이어 머리 바로 위까지 낮게 내려오며, 이를 점프 박치기로 파괴하는 기믹이 있습니다. 이후 스토리 반전(2회차/후반부)에서는 `ESC` 기능이 봉인된 채 실시간 `Space` 점프만으로 등반하여 정상의 ESC 보스를 타격하는 모드 전환을 고려해 입력과 캐릭터 상태를 유연하게 분리합니다.

## 2. 핵심 코딩 철학 (단순성 & 가독성 최우선)

1. **최대한 단순하고 깔끔하게 작성 (KISS & YAGNI)**
   * 당장 기획서에 없는 미래의 기능을 대비해 불필요한 인터페이스, 추상 클래스, 복잡한 디자인 패턴을 남발하지 마세요.
   * 한 스크립트는 **단 하나의 명확한 역할(단일 책임 원칙)**만 수행하도록 작게 유지합니다. (스크립트 하나당 150~200줄 이내 권장)
2. **수정과 파악이 쉬운 직관적 코드**
   * 제3자나 기획자가 인스펙터(Inspector)와 코드만 봐도 어디서 점프 세기, 중력, 반사 계수, 타이머 시간을 고쳐야 하는지 즉시 알 수 있어야 합니다.
   * 중첩 조건문(`if` 안의 `if` 안의 `if`) 대신 **얼리 리턴(Early Return)** 패턴을 사용하여 들여쓰기 깊이를 최대 2단계 이내로 유지합니다.
3. **매직 넘버(Magic Number) 절대 금지**
   * 코드 내부에 `0.3f`, `3.0f`, `15f` 같은 숫자를 직접 하드코딩하지 마세요.
   * 모든 수치는 반드시 의미 있는 변수명(`maxChargeTime`, `crumbleDelay`, `wallBounceMultiplier`)으로 선언하고 인스펙터에 노출합니다.

## 3. 가독성 및 인스펙터(Inspector) 표기 규칙

유니티 에디터에서 기획자와 개발자가 수치를 쉽게 수정할 수 있도록 아래 어트리뷰트(Attribute)와 주석 규칙을 **필수로 적용**합니다.

### 3.1 인스펙터 그룹화 및 한글 툴팁 필수 표기
* 외부에 노출할 변수는 `public` 대신 **`[SerializeField] private`**를 기본으로 사용합니다.
* 연관된 변수들은 **`[Header("카테고리명")]`**으로 묶고, **`[Tooltip("한글 설명")]`**과 **`[Range(최소, 최대)]`**를 적극 활용하여 마우스를 올렸을 때 역할을 바로 알 수 있게 합니다.

```csharp
[Header("점프 충전 설정")]
[Tooltip("스페이스 바를 최대로 누를 수 있는 시간 (초)")]
[Range(0.1f, 2.0f)]
[SerializeField] private float _maxChargeDuration = 1.0f;

[Tooltip("최대 충전 시 적용되는 기본 도약 힘")]
[SerializeField] private float _maxJumpForce = 18.0f;

[Header("벽 박치기 반사 설정")]
[Tooltip("벽 충돌 시 남은 속도를 얼마나 유지할지 결정하는 반사 계수 (0~1)")]
[Range(0f, 1f)]
[SerializeField] private float _wallBounceRetention = 0.75f;
```

### 3.2 코드 구역 분리 (`#region` 또는 명확한 구분 주석)
* 모든 MonoBehaviour 스크립트는 변수와 함수의 위치가 뒤섞이지 않도록 항상 아래 순서를 유지합니다:
  1. **상수 및 열거형 (`const`, `enum`)**
  2. **인스펙터 노출 변수 (`[SerializeField]`)**
  3. **내부 상태 및 캐싱 변수 (`private`)**
  4. **유니티 생명주기 함수 (`Awake`, `OnEnable`, `Start`, `Update`, `FixedUpdate`)**
  5. **공개 기능 함수 (`public` 메서드)**
  6. **내부 구현 및 보조 함수 (`private` 메서드)**

### 3.3 수정 포인트 태그 주석 규칙
* 사람이 자주 건드리거나 추후 작업이 필요한 곳에는 검색(`Ctrl + F`)이 쉽도록 표준 태그 주석을 남깁니다:
  * `// [TUNE]`: 기획 밸런싱을 위해 수식이나 수치를 자주 조절해야 하는 핵심 로직 구간
  * `// [TODO]`: 추후 사운드, 이펙트, 애니메이션 연결이 필요한 자리
  * `// [NOTE]`: 물리 연산이나 일시정지 예외 처리 등 지우면 안 되는 중요한 이유 설명

## 4. 네이밍 컨벤션 (이름 짓기 규칙)

코드만 읽어도 변수와 함수의 성격을 구분할 수 있도록 아래 규칙을 통일합니다.

| 대상 | 표기법 | 규칙 및 예시 |
| :--- | :--- | :--- |
| **클래스 / 구조체 / 열거형** | `PascalCase` | 역할을 명확히 표현 (`JumpRecorder`, `TrajectoryPredictor`, `CrumblePlatform`) |
| **인터페이스** | `I` + `PascalCase` | `IBounceable`, `IPauseReactive` |
| **메서드 (함수)** | `PascalCase` | 반드시 **동사**로 시작 (`StartRecordingJump()`, `ExecuteNextJump()`, `FlipDirection()`) |
| **인스펙터/내부 private 변수** | `_camelCase` | 앞에 언더바(`_`)를 붙여 지역 변수와 즉시 구분 (`_currentChargeTime`, `_facingDirection`) |
| **매개변수 / 지역 변수** | `camelCase` | 언더바 없이 소문자로 시작 (`holdDuration`, `bounceNormal`) |
| **프로퍼티 (Property)** | `PascalCase` | 외부 읽기 전용 공개 시 사용 (`public bool IsPaused { get; private set; }`) |
| **불리언 (`bool`) 변수** | `is`, `has`, `can` 접두어 | 상태를 한눈에 파악 (`_isPaused`, `_canInputJump`, `_isExecutingQueue`) |
| **상수 (`const`)** | `UPPER_SNAKE_CASE` | `MAX_JUMP_QUEUE_COUNT = 4` |

## 5. 《일시정지!》 맞춤형 아키텍처 및 물리 설계 규칙

이 게임에서 가장 버그가 나기 쉬운 **'일시정지 중 사전 입력'**과 **'예상 궤도 표시 vs 실제 물리 이동의 일치'**를 깔끔하게 구현하기 위한 핵심 설계 수칙입니다.

### 5.1 기능별 스크립트 분리 (God Class 금지)
`Player.cs` 하나에 입력, 물리, 궤도 그리기, UI, 사운드를 전부 넣지 말고 아래와 같이 깔끔하게 역할을 나눕니다.
* **`GameStateManager`**: 게임의 현재 상태(`NormalPlay`, `PausedRecording`, `ExecutingQueue`, `EscDisabledBossMode`)를 관리하고 상태 변경 이벤트를 방송(`event Action`)합니다.
* **`JumpInputRecorder`**: 일시정지 상태에서 `Space` 입력 시간을 측정해 `JumpCommand`(점프 세기 데이터) 리스트를 생성하고 큐에 저장합니다.
* **`PlayerJumpMotor`**: 큐에서 넘겨받은 `JumpCommand`를 바탕으로 실제 포물선 도약, 중력 적용, 얼음 미끄러짐, 벽 박치기 시 방향 전환(`_facingDirection *= -1`)을 수행합니다.
* **`TrajectoryVisualizer`**: 초반 구간에서 `JumpInputRecorder`의 예약 리스트를 받아 `PlayerJumpMotor`와 **완전히 동일한 계산 함수**로 예상 궤도 점(LineRenderer 또는 도트 스프라이트)을 화면에 그립니다. (높이 구간에 따라 투명도/표시 여부를 조절)
* **`PlatformGimmick` 계열**: `IceSurface`(마찰력 및 경사 미끄러짐), `CrumblePlatform`(3초 타이머 및 UI 연동), `PauseTextTarget`(정상에서 내려온 '일시정지' 글자 타격 판정) 등 기믹별로 컴포넌트를 분리해 조립합니다.

### 5.2 일시정지(`ESC`) 구현 시 `Time.timeScale = 0` 의존 주의
* 유니티 기본 `Time.timeScale = 0f`만 무작정 사용하면 일시정지 중 UI 연출이나 입력 감지, 특정 타이머 제어가 꼬이기 쉽습니다.
* `GameStateManager.IsPaused` 상태를 기준으로 물리 이동 컴포넌트들이 속도를 잠시 해동/동결하도록 설계하고, 일시정지 중 측정해야 하는 `Space` 누름 시간은 반드시 **`Time.unscaledDeltaTime`**을 사용하여 프레임이나 타임스케일에 영향받지 않고 정확히 측정합니다.

### 5.3 궤도 예측과 실제 이동의 오차 방지 (결정론적 물리 수칙)
* 초반부에 **보조 궤도 가이드가 보여준 위치**와 일시정지 해제 후 **실제 캐릭터가 착지·벽 반사하는 위치**가 다르면 플레이어는 큰 불합리함을 느낍니다.
* 이를 방지하기 위해 점프 초기 속도 계산, 중력 가속도, 벽 충돌 반사 수식은 별도의 순수 계산 함수(예: `JumpPhysicsCalculator.CalculateStep(...)`)로 한 곳에 작성하고, **실제 이동(`FixedUpdate`)과 궤도 시뮬레이션이 똑같은 수식과 물리 설정값을 공유**하도록 작성합니다.

## 6. 유니티 성능 및 안정성 필수 규칙

1. **`Update()` 내 `GetComponent` 및 `Find` 호출 금지**
   * `GetComponent<T>()`, `FindObjectOfType<T>()` 등 무거운 탐색 함수는 반드시 `Awake()`에서 한 번만 호출하여 변수에 캐싱해 둡니다.
2. **참조 누락 방지 (`[RequireComponent]`)**
   * `Rigidbody2D`, `Collider2D` 등 필수 컴포넌트가 필요한 스크립트 상단에는 `[RequireComponent(typeof(Rigidbody2D))]`를 명시하여 실수로 컴포넌트를 빼먹는 에러를 원천 차단합니다.
3. **물리 연산과 입력 감지의 분리**
   * 키보드(`Space`, `ESC`) 입력 감지와 UI 갱신은 **`Update()`**에서 처리합니다.
   * 실제 리지드바디 이동 및 물리 충돌 처리는 **`FixedUpdate()`**에서 처리하여 모니터 주사율(프레임)이 달라도 항상 동일한 점프 높이와 거리가 나오도록 보장합니다.
4. **문자열 하드코딩 대신 상수/해시 사용**
   * 태그 비교 시 `other.tag == "Wall"` 대신 `other.CompareTag("Wall")`을 사용합니다.
   * 애니메이터 파라미터는 `Animator.StringToHash("IsJumping")`로 미리 캐싱해 사용합니다.

## 7. Codex / AI에게 코드 작성을 시킬 때의 출력 포맷 규칙

AI는 사용자의 요청에 따라 C# 스크립트를 작성하거나 수정할 때 항상 다음 규칙을 지켜 출력해야 합니다.

1. **스크립트 상단 요약 주석 필수**: 모든 클래스 선언 바로 위에 `/// <summary>` 주석으로 **이 스크립트의 역할**과 **인스펙터에서 연결해야 할 필수 오브젝트**를 2~3줄로 명확히 적습니다.
2. **생략 없는 전체 코드 또는 명확한 변경 지점 표기**: 코드를 수정할 때 `// ... 기존 코드 생략 ...` 때문에 앞뒤 맥락이 깨지지 않도록 주의하고, 수정된 부분 위아래에 `// [수정됨: 이유]` 주석을 달아 사용자가 변경점을 한눈에 파악할 수 있게 합니다.
3. **에디터 적용 가이드 함께 안내**: 코드 제시 후 마지막에 **"유니티 에디터 설정 방법"**(어느 오브젝트에 붙이는지, 인스펙터에서 어떤 값을 넣어야 하는지, 필요한 Tag/Layer는 무엇인지)을 3줄 이내로 간단명료하게 덧붙입니다.
