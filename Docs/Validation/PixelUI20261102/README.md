# 픽셀 메인·설정·관리 메뉴 · 2026-11-02

시작 씬은 `Assets/Scenes/MainMenu.unity`다. Build Settings 첫 항목이며 게임 시작은 `Stage09_RGBKeyboard`로 연결된다. 다른 디자인 씬에 새 메뉴를 일괄 삽입하지 않았다.

## 구현

- 제공된 첫 번째 그림을 메인 배경으로 사용하고 투명하게 분리한 타이틀·게임 시작·설정·게임 종료를 왼쪽에 배치했다.
- 시작과 메인 복귀는 검게 닫힘 → 씬 로딩 → 서서히 드러남으로 전환한다. `화면 전환 · 페이드`의 PauseSceneTransition에서 시간을 바꿀 수 있다. 실제 시간을 사용하며 긴 프레임으로 전환이 한 번에 생략되지 않도록 제한한다.
- 메인 설정은 같은 배경 위에 BGM/SFX를 세로로, 게임 내 설정은 검은 배경 위에 BGM 왼쪽·SFX 오른쪽으로 배치했다.
- 프레임·금색 채움·손잡이를 실제 uGUI Slider로 구성했다. 음악과 효과음을 독립적으로 조절하고 PlayerPrefs에 저장한다. 게임의 기존 전체 음량과 각각 곱해지며 효과음 손잡이를 놓으면 확인음을 들을 수 있다.
- 게임 우측 상단 버튼은 ESC 점프 계획과 별개인 관리 메뉴다. 게임의 위치·속도·예약 점프·타이머를 보존한다. 이어하기는 원래 기록/재생 상태로 돌아간다. 기록 중 누르고 있던 입력은 기존 설정 정지 규칙대로 현재 세기까지만 확정한다.
- 원형 화살표는 경고창을 열고, `예`에서만 처음부터 다시 시작한다. `아니오`는 확인창만 닫는다. 문 아이콘은 메인으로 복귀한다.
- UI는 런타임에 그림 하나로 그리는 방식이 아니라 저장된 Canvas/Image/Button/Slider/Text 오브젝트다. Hierarchy에서 각 화면·RectTransform·연결을 직접 수정할 수 있다. 기존 코스와 옥상은 다시 생성하지 않았다.
- MainMenu의 `메인 화면 Canvas · 1920x1080`, 09번의 `게임 관리 Canvas · 편집 가능`에서 편집한다. 각 관리 화면은 기본 비활성이므로 편집할 때 해당 화면만 켜고 수정 후 원래 상태로 저장한다.
- `com.unity.ugui` 2.0.0을 프로젝트 의존성에 추가했다. 기존 한국어 폰트 GameKorean을 재사용했다.

## 실제 Editor Play 검증

Unity 6000.3.22f1에서 저장 씬을 Play하여 검사했다. 자동 입력/Unity UI 이벤트를 사용했으며 외부 기기에서 손으로 플레이한 증거는 아니다.

1. 메인 설정 버튼의 실제 GraphicRaycaster 적중과 PointerClick 처리 확인.
2. 음악 23%, 효과음 61% 설정 시 실제 두 AudioSource 음량 독립 확인. 09번으로 이동해 동일 비율 유지 확인.
3. 두 Slider에 PointerDown/Drag/PointerUp을 전달해 음악 약 29%, 효과음 약 71%로 변화 확인. SFX 놓기 확인음 호출 포함.
4. 시작 페이드 31개 표본에서 MainMenu 알파 약 0.018 → 1, 09번 알파 약 1 → 0 확인. `FadeSamples.json`에 저장.
5. 실제 도약 중 `(-9.06, 1.34)`, 속도 `(4.71, 4.66)`, 남은 점프 1개 상태에서 관리 정지를 열었다. 여러 호출 사이 실제 시간이 지나도 위치·속도·남은 점프가 동일하고 이어하기 직후에도 동일함을 확인했다.
6. 재시작 `아니오`는 진행 유지, `예`는 시작점 `(-10, 0)` 및 예약 0으로 초기화됨을 확인했다.
7. 문 버튼으로 MainMenu 복귀, AudioListener 정지 해제, 전환막 한 개만 존재함을 확인했다. 검사 전 음량 설정은 복원했다.
8. 픽셀 UI를 붙인 상태에서 기존 실제 입력 드라이버로 **99회 도약·25개 예약 묶음·옥상 중앙 착지·어퍼컷 적중·크레딧**까지 다시 통과했다. `Route1~5.json`, `RouteEnding.json` 및 인접 RandomStage09 검증의 `Runtime.json` 참조.
9. 한국어와 백분율의 실제 UI 메시 생성 및 GameView 표시를 확인했다. Console 오류 0. 최종 편집 상태는 Play 종료·검증 리로드 잠금 해제·씬 저장 상태로 확인한다.
10. 메인 게임 종료 버튼의 레이캐스트·PointerClick을 실행하여 Editor Play 종료를 확인했다. 편집 상태에서는 페이드 CanvasGroup을 투명하게 저장해 UI 편집 화면을 가리지 않는다.

실제 GameView 캡처: `01_Main.png`, `02_MainSettings.png`, `03_Pause.png`, `04_PauseSettings.png`, `05_Confirmation.png`.

이번 요청에서는 새 Windows/APK 빌드와 Android 실기기·터치 하드웨어 검사를 수행하지 않았다. 종료 버튼의 실행 빌드 프로세스 종료는 코드 연결 확인 범위다.

## 그림 출처와 편집 기록

사용자 제공 `KakaoTalk_20261102_141352707.png` 및 `_01`~`_04`를 사용했다. 첫 그림은 원본 그대로 보존했다. 나머지 네 시트는 imagegen의 **edit / transparent_background=true**로 검은 외부 배경만 투명화했다.

프롬프트 요지: 외부 검은 배경만 알파로 제거하고 한국어 글자·오브젝트·도트·색·위치·간격을 유지하며, 어두운 패널 내부는 불투명하게 보존한다. 재디자인하거나 새 부품을 넣지 않는다.

저장 경로는 `Assets/Art/PixelUI20261102/{MainBackground,MenuSheet,PauseSheet,SettingsSheet,PanelSheet}.png`다. 원본 생성 결과는 Codex generated_images 폴더에도 남겨두었다. `PausePixelUiArt`는 이 PNG의 픽셀을 수정하지 않고 영역을 Sprite 자산으로 분리한다. `Sprites` 폴더의 부품은 제공 시트의 각 영역을 참조한다.
