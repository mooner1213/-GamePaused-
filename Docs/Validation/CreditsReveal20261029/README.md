# 크레딧 암전·등장 연출 수정

수정 범위는 `PauseHudMenuScreen.cs`와 `PauseHudEffects.cs`의 마지막 크레딧 화면이다. 어퍼컷, 문구 파괴, 하늘 상승, 씬 배치, 옥상 자산은 이 작업에서 수정하지 않았다.

기존 구현은 문구 파괴 후 경과 시간을 크레딧에도 사용했다. 실제 크레딧 진입 시 이 시계는 이미 약 6초였으므로 암전과 대부분의 스크롤이 끝난 상태로 표시됐다. 이제 `PauseGame.EndingElapsed`를 사용해 크레딧 화면 진입 시점부터 계산한다.

순서는 대기 → 부드러운 암전 → 아래에서 타이틀·본문·크레딧이 함께 올라오기 → 기존 위치에서 감속·정지다. 재도전 버튼도 스크롤 정지 후 표시한다. 기존 문구와 최종 배치값은 유지했다.

기본값 기준:

- 암전 전 대기 0.8초
- 암전 1.3초, 최대 불투명도 0.88
- 스크롤 시작 Y 790 → 정지 Y 190, 평균 속도 96, 약 6.25초
- 크레딧 진입 약 8.35초 후 정지

## 검증

`Timeline.txt`: 0~20초 401개 시각에서 암전의 연속 진행, 암전 완료 전 스크롤 대기, 위쪽 이동, 정지 이후 정확한 위치 유지를 확인했다.

`Runtime.txt`: MainScene Editor Play에서 실제 어퍼컷과 문구 파괴를 거쳐 크레딧에 진입했다. 진입 시 파편 시계 약 6.1초와 별개로 크레딧 시계 0초, 암전 0, 시작 Y 790을 확인했다. 8.8초에 기존 Y 190으로 정지했고 추가 10초 진행해도 동일했다. 캐릭터는 기존 어퍼컷 03번을 유지했다. 정지 안내 로그는 한 번만 출력됐다.

실제 Editor Play 화면 캡처:

1. `01_크레딧시작.png`
2. `02_서서히암전.png`
3. `03_아래에서올라오기.png`
4. `04_기존위치에정지.png`

중간 자동 검사는 지연된 Editor 스크립트 재로드로 한 번 중단됐다. 재생을 다시 시작해 검증 구간에서만 임시 어셈블리 재로드 잠금을 사용했고, 종료 시 잠금을 해제하고 Play를 정지했다. 게임 코드에 재로드 잠금이나 검증 드라이버를 추가하지 않았다.

컴파일과 MainScene의 마지막 크레딧 화면을 확인한 범위이며 새 빌드·Android 실기기 검사는 수행하지 않았다.

## Inspector 조절 위치

게임 관리자 오브젝트의 `Pause Hud` → `Effects` → `크레딧 암전과 아래에서 올라오는 연출`에서 암전 대기·시간·불투명도와 크레딧 시작점·정지점·속도를 조절한다. 기존 씬에 저장된 설정값을 그대로 사용하며 추가 연결은 필요 없다.
