# 2026-10-29 옥상·어퍼컷 검증

## 변경

- 엔딩에서 `EndingUppercut_01` → `02`만 느리게 재생하고 `03`을 표시하는 틱에 문구를 파괴한다. 이후에는 `03`을 유지하며 상승한다.
- 실제 원화의 가장 높은 불투명 픽셀과 최종 확대 배율로 주먹 위치를 계산한다. 캐릭터 몸통 판정 높이는 문구 충돌에 사용하지 않는다.
- 충돌 틱에는 카메라를 이동하지 않는다. 이후 추적 여유를 서서히 좁혀 빠른 상승에서도 주먹을 화면에 남긴다.
- 원형 옥상은 낮은 시점의 수평 타원이다. 앞벽·바닥·뒤벽을 분리했고 이전 장식 Tilemap은 비활성으로 보존했다.

## 확인한 범위

`UppercutModel.txt`: 좌우 2방향 × 4개 시간 간격, 총 8조건. 01→02→03 순서, 충돌과 마지막 자세의 동시성, 주먹 목표 오차, 충돌 후 03 유지 통과.

`UppercutRuntime.txt`: MainScene의 실제 Unity Editor Play에서 마지막 아래 발판의 도약으로 정상 착지를 인정한 뒤 ESC·점프 입력을 전달했다. 충돌 직전 02, 충돌 틱 03, 주먹 목표 오차 약 0.00000009m, 충돌 틱 카메라 이동 0m를 확인했다. 크레딧 중에도 03을 유지하며 Y 10017.19까지 연속 상승했고 주먹이 화면 안에 있었다. 자동 입력은 실제 PauseGame/PauseSimulation/캐릭터 뷰를 호출했다.

`MainScene_Roof.png`, `Uppercut01.png`, `Uppercut02.png`, `Uppercut03_Hit.png`, `Uppercut04_Ascent.png`는 Editor Play 화면 캡처다. `09_원형옥상_조립.png`는 Sprite 레이어 조립 렌더다.

`Scenes.txt`: 15개 디자인 씬과 MainScene에서 기존 맵 물리 및 모든 Tilemap의 내용·색·변환을 비교했다. 기존 팔레트 파일 해시도 동일했다. 원형 시안은 새 Sprite 세 장으로만 구성된다. 최종 RGB 바닥의 열 내부 투명 픽셀 0, 부분 투명 픽셀 0을 확인했다.

실행 검증은 MainScene의 마지막 도약과 엔딩 범위다. 다른 15개 씬의 전체 등반, 새 Windows/APK 빌드, Android 실기기 검증은 수행하지 않았다.

## Inspector 조절

게임 관리자의 `정상 엔딩 동작`에서 `Duration`과 `Slow Motion Speed`를 조절한다. 실제 적중까지의 시간은 두 값의 나눗셈이며 기본값은 1.3 / 0.35 ≈ 3.71초다. 카메라의 `Ending Release Seconds`는 충돌 후 추적 전환 시간이다. 실제 문구 위치와 03번 주먹 픽셀은 자동으로 연결되어 별도 좌표 입력이 필요 없다.
